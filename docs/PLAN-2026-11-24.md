### P3 · 文字颜色随壁纸自适应（**中**，需批准后再做）

**目标**：深壁纸 → 浅字，浅壁纸 → 深字。**动态壁纸不承诺**（见取舍）。

**方案 T1（推荐）：壁纸文件亮度采样**

- 新增 `float WallpaperLumUnder(const RECT& screenRect)`，**不复用整条重绘链**：
  1. 读 `WallpaperPath()`（269 行那段代码保留下来专门用于此）
  2. 解码壁纸为缩略图（宽度 ≤ 1024，**每次壁纸变更只解一次**）
  3. 用 `WallpaperStyle()` 同一套 fill/fit/stretch/center/tile 映射，把窗口矩形换算成图片坐标，裁剪（越界钳位）
  4. 对裁剪区做平均亮度（复用 `ComputeLuminance` 的算法即可）
- **缓存**：`path + size + mtime` 不变则复用；失效时机 = 启动 / `WM_SETTINGCHANGE` / 移动或 resize（**200ms 去抖**）/ 显示器几何变更
- **失败回退**：路径为空、解码失败、权限不足、动态壁纸（注册表路径已失效）→ `lum = 0.5`，**等价于今天的行为，零回归**
- **代价**：每次壁纸变更一次解码（约 10–30ms，一次性）；无逐帧开销
- **已知局限**：只按主显示器几何换算（与现有实现一致）；多显示器不同壁纸不精确

**方案 T2（更保守）**：设置面板加「文字：自动 / 浅色 / 深色」三态，自动 = 现有启发式。不读壁纸，纯配置 + 一个枚举。**我建议 T1**，因为它才是真正修掉「指南 §14 坑 10」；T2 只是把问题交给用户。

**验证矩阵（5 组）**

| 场景 | 期望 |
| --- | --- |
| 深色壁纸（如 `1E1E1E` 纯色） | `TextColor()` 返回 `(247,247,250)` 浅字 |
| 浅色壁纸（如 `F5F5F5`） | 返回 `(45,45,48)` 深字 |
| 中间灰（`808080`） | 按 0.58 阈值取一侧，记录实际值 |
| Wallpaper Engine 动态壁纸 | 回退 0.5 → 与今天一致 |
| 无壁纸/路径失效 | 回退 0.5 |

另加**失败注入**：把壁纸路径改成不存在的文件，确认不崩溃、回退 0.5。

**风险**：中 —— 新增解码路径；已设计三级回退，且不改渲染主链（只改 `TextColor()` 的 `lum` 入参来源）。

### P4 · 高斯模糊「摘眼镜」（**高，本阶段只做设计评审，不写代码**）

三条路线对比：

| 路线 | 做法 | 判断 |
| --- | --- | --- |
| **1) 静态壁纸模糊层**（推荐） | 解码壁纸 → 模糊窗口覆盖区 → 作为背景层绘制，透明度仍由「不透明度」控制；`blur` 半径滑块回归（第 4 个滑块复活） | 可做。`blur=0` 时像素与今天**完全一致** |
| 2) DWM SystemBackdrop（Mica/Acrylic） | 需要非分层普通窗口 | **否掉**：等于推翻 `UpdateLayeredWindow` 架构，圆角/逐像素/文字管线全部重做 |
| 3) 复活旧截屏链 | 截屏 → 高斯模糊 → 贴回去 | **不推荐**：动态壁纸可用，但重演卡顿/闪烁/陈旧画面，正是被废弃的原因 |

**取舍必须你拍板**：路线 1 在**动态壁纸（Wallpaper Engine）下会失真**（模糊的是静态壁纸帧，不是实时画面），需要退化为真透明或接受视觉不一致。
**风险**：高 —— 改渲染主链 + 配置项（`blur` 重回 `Config`）+ 设置面板再排一次版（与 P2 强耦合，应在 P2 之后）。

### P5 · DPI per-monitor v2（**高，本阶段只出方案**）

- **现状**：`SetProcessDPIAware()`（3074，系统级）+ manifest `dpiAware=true`；**无 `WM_DPICHANGED`**；UI 字体 px 取自 `SPI_GETNONCLIENTMETRICS`，图标字形用 `S()`；`cfg.width/height` 直接当设备像素用于 `SetWindowPos`
- **要升级必须同时做**：manifest 加 `dpiAwareness = PerMonitorV2` → 加 `WM_DPICHANGED` 处理 → **重建全部字体**（先 delete 旧 `Font`/`HFONT`，否则泄漏）→ 重新布局 → 定义 `cfg` 尺寸语义（设备像素 or 逻辑像素，牵涉老配置迁移）
- **结论**：**不建议现在动**。除非你经常在缩放比不同的多显示器之间拖这个小组件。

### P6 · 字体改为取系统字体（用户追加需求，已完成）

**问题**：`InitFonts` 原来取 `SPI_GETNONCLIENTMETRICS.lfMessageFont`，那是「消息框字体」，不是资源管理器画桌面图标标签用的字体。实测本机两个值并不相同：

| 来源 | face | lfHeight | 说明 |
|---|---|---|---|
| `HKCU\...\WindowMetrics\IconFont` | Microsoft YaHei | -12 | 桌面图标标签实际用的就是它 |
| `lfMessageFont` | Microsoft YaHei UI | -15 | 原实现采用，比桌面标签大一号 |

**改法**：新增 `ReadSystemLabelFont(LOGFONTW&)`，顺序 ① 注册表 `IconFont`（校验 92 字节、`REG_BINARY`、face 非空、`lfHeight≠0`）→ ② `SPI_GETICONTITLELOGFONT` → ③ `lfMessageFont`；`px=|lfHeight|` 钳 8~40；face 名剥离尾部空格（本机注册表值确实带一个空格，不剥会导致 `FontFamily` 失败而静默退回 Segoe UI）；`g_fontSmall = max(px-1.5, 9)`。图标字形（`Segoe Fluent Icons` / `Segoe MDL2 Assets`）不属于文字字体，未改动。

**效果**：本机 UI 文字 15px → 12px（逻辑），视觉上首次与桌面图标标签完全同款；用户以后在显示设置里改图标字体大小，重启小组件即跟随。

**验证**：`-Wall -Wextra` 编译 0 error / 0 新增 warning；离屏渲染 `main_font.png`、`set_font.png` 逐项目视无重叠；命中测试 24/24 通过；隔离 APPDATA 下真实进程两次抓图 **0 像素差异**（确定性），与改字体前的 `dev2_run2.png` 相比文本色像素 2334 → 1368（字号变小的预期结果），布局与图标未变。`build.ps1` 未改动，`GlassDock.exe` / `installer\setup.exe` / `release\GlassDock-Setup-1.0.0.exe` 已按新字体重建（531,968 B / 971,776 B / 971,776 B）。

**备份**：`build\GlassDock.exe.p1p2.bak`、`build\GlassDock-Setup-1.0.0.exe.p1p2.bak`（改字体前的 P1+P2 版本）。

**修正 1（用户截图反馈后）**：第一版把注册表里的 `lfHeight=-12` 直接当设备像素用了，漏了 `* g_scale`——`IconFont` 存的是 96dpi 单位，125% 缩放下应该是 15px。结果文字比改字体前小 3px，用户一对比资源管理器就发现了。现已改为「来自注册表的乘 `g_scale`，来自 SPI 的不乘」，字号回到 15px，与资源管理器列表同高。

**修正后与改字体前成品的像素差异**：`dev2_run2.png`（旧·YaHei UI 15px）vs `v15_widget.png`（新·YaHei 15px）＝ **77 / 235200 像素**、`maxDelta=1`（1/255），文本色像素数同为 2334 —— 即换 face 本身几乎看不出来，真正被用户看见的是那次字号缩水。

**与资源管理器仍存在的差异（不改）**：资源管理器用 ClearType 彩色次像素，笔画显得更「实」；小组件用灰度 AA，避免在任意壁纸上出现彩色毛边——这正是当初解决「发虚」时选定的路线，不为了像素级像 Explorer 而改回去。
